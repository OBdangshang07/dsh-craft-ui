# Craft UI 下一阶段功能计划

状态：0.4.0 三模块已实施，0.5/0.6 仍为提案。日期：2026-09-22。

基线：Craft UI 0.3.1；本机 DeepSeek Harness 0.1.7-alpha.1。

原计划形成于 0.3.1 推送之后（`main` 提交 `8fa3a8bf963cdbc2561e9ef3bf880cd7b3c24af2`）。用户随后授权按此计划开发，0.4.0 已完成隔离验证。日常插件安装和 GitHub 推送均按用户当轮授权执行，不强制中断正在运行的 DSH 任务。

## 0.4.0 实施说明

追加需求：0.4.0 同时包含默认启用的 Minecraft 风格推理等级滑条，可在设置恢复旧菜单；复用 DSH 原有模型目录与选择接口，不改模型能力或正在执行的请求。面板已压缩为常规四档下的 288 × 163 像素，顶部提供明确的「模型 / 切换 ▾」按钮。

已实现图片阅览条、图片工作台、会话书签三个模块及 Java 风格双主题。代码通过公开插槽接入，不改 Harness 本体，不提交额外模型请求。详细使用说明见中英文 README。下文保留路线设计，以下是当前实现与设想的明确差异：

- 图片采用逐工具缩略图与回合末汇总；不覆盖 DSH 的原生 Chat 分组，折叠工具组仍由上游控制。
- 来源定位在书签册中按事件精确读取原文，不强制滚动主对话。更早的可收藏消息需要先在 Chat 中载入。
- 标注可以保存、编辑、查看修订、追加草稿和导出带框线的 PNG；不自动重新附图。导出的 PNG 不包含说明文字，文字与坐标通过草稿反馈。
- 书签按 profile + Session 身份隔离，分支不自动继承。导入只接受同一 Session，跳过已有 ID，不恢复历史修订和替代关系。
- 不做自动语义冲突识别：约束并列展示、旧记录保留、替代关系由用户明确指定。
- 浏览器已验证真实 DSH 持久附件、公开插槽、Host 保存/原文查询与刷新恢复；大量边界组合使用合成夹具验证，不等同于真实模型在线验收。

## 1. 产品方向

从 Minecraft 主题层逐步增加可选的效率工具，重点解决三个问题：看清 AI 实际读了什么；准确指出哪里需要修改；在长任务里保留可追溯的成果和决定。

下一版建议命名为 **0.4.0「地图与书签」**，集中交付图片展示、图片工作台、消息书签三个模块。其余能力分阶段推进，不在一次更新里改动任务执行、模型请求和文件恢复。

功能名称使用普通中文，Minecraft 元素用于外观与辅助图标。所有功能可以单独关闭；禁用后恢复 DSH 原生界面，不影响会话和文件。

## 2. 已有能力与真正需要补的部分

以下基于本机包的 README、公开契约和关键实现核查；包具备能力不代表所有用户配置都启用了它。没有找到某项功能，不等于对全部第三方插件作出了穷尽结论。

| 领域 | DSH 已有 | Craft UI 应补充什么 |
| --- | --- | --- |
| AI 读取图片 | `read_image`、持久附件引用、工具结果图片画廊；读取卡片默认折叠 | 更直接可见的缩略图、连续读取汇总、来源定位 |
| 图片预览 | 附件放大器、侧栏图片预览；侧栏已有缩放 | 统一查看体验、双图对比、标注反馈；不是重新发明图片预览 |
| 文件交付 | `present`、交付卡片、文件链接、文档预览 | 交付证据整理、可选的历史版本留存 |
| 代码变更 | 回合变更摘要、左右/统一 diff | 跨重启留存以及后续安全恢复；现有摘要随 Host/Session 生命周期失效 |
| 搜索与引用 | 会话内容搜索、`@file`、`@session`、会话置顶 | 消息级书签、带来源的决定卡片、定位到具体事件 |
| 计划与执行状态 | 待办、目标、子代理、后台 Jobs、可选 Schedule；Craft UI 已有对应 HUD | 跨会话待处理汇总，避免折叠工作区里的待确认被漏掉 |
| 统计与上下文 | 上下文压力、回合 token 用量、性能统计、压缩 | 用户可审阅的精简交接包，不重做统计条或压缩引擎 |
| Checkpoint | 执行前日志落盘、崩溃恢复策略 | 用户可操作的文件快照恢复；两者不是同一个功能 |

## 3. 0.4.0：三个主要模块

### A. 对话内图片阅览条（最高优先级）

目标是用户截图中的体验：AI 成功读取图片后，对话里就能看到图片，而不是只见路径或折叠的工具日志。

交互设计：

- 在图片工具结果位置默认显示紧凑缩略图；连续读取的图片争取聚合成「已读取 3 张图像」的可折叠组。
- 桌面默认展示最多三张，更多显示「查看全部 N 张」；窄屏改为两列或单列，避免出现新的横向遮挡。
- 缩略图保持完整比例，不强制裁掉内容；显示简短文件名，悬停或聚焦可见来源、尺寸、时间。
- 点击进入查看器，支持上一张/下一张、适应窗口、100%、键盘导航；独立的「定位读取记录」返回来源。
- 标题计数按成功读取结果生成；读取中、读取失败、附件失效分别显示，不根据助手正文中的路径猜测。
- 「已读取」只证明工具成功返回了图片，不宣称模型已经理解图片或完成质量验收。
- 同一回合内相同附件内容可合并展示，并注明读取次数；同路径的新内容保留为不同版本。

数据与历史：

- 复用 DSH 持久附件引用和 `uiConversation.imageUrl(sessionId, attachment)`，优先展示当时读取的附件内容，不偷偷改成磁盘上目前的同名文件。
- 部分图片在 DSH 入库时可能已经缩放或转换：应标注「读取时附件」，不能把它称为未经处理的原始文件。
- 用 Session、事件/调用身份、附件身份建立索引，支持刷新、历史加载、重新连接和分支会话；附件丢失时保留来源记录并显示不可用。
- 不遍历磁盘搜图，不因为展开预览而再次调用模型，也不把所有历史图片自动重新发给模型。
- 第一阶段覆盖标准 `read_image` 与可识别的嵌套调用。其他工具仅在返回兼容的持久图片引用时接入；任意终端输出、远程 URL 和生成图片不自动混作「已读取」。

集成可行性门槛：

- 已确认 `tool.call.toolview`、`tool.call.images` 和回合末 `conversation.chat.turnTail` 扩展入口存在。
- 单个工具卡片默认显示和回合末汇总有明确接入方向；连续多工具的实时聚合需要先验证公开节点/渲染接口。
- DSH Chat 已占用自己的 Group Definition，不能直接注册第二套分组去覆盖原生逻辑。若缺少合适入口，0.4.0 先交付默认可见的逐调用缩略图与回合汇总，将跨调用实时分组列为上游扩展点需求，不抓取 DOM 或替换整套聊天渲染器。

### B. 图片工作台：对比与定点反馈

这是超出目前基础图片预览的核心新增功能，特别适合 UI 调整、Minecraft 建筑、贴图和生成图片迭代。

- 从阅览条选择两张图，提供左右对比；同尺寸图片增加滑杆对比。尺寸不一致时明确标出，不能自动拉伸制造错误差异。
- 支持同步缩放与平移；像素素材提供「最近邻」模式，照片/界面截图默认正常采样。只改变预览，不改文件。
- 用矩形框和编号标注问题，输入「这里挡住了」「这块颜色偏暗」等说明。
- 点击「加入反馈」后，把源图引用、区域坐标和说明放入输入草稿，由用户检查再发送；不自动发消息、不覆盖已有草稿。
- 标注保存为独立元数据，不直接涂改源文件；必要时经用户选择生成一张带标注的反馈附件，明确它是派生图片。
- 坐标使用相对图片尺寸的归一化值，并绑定附件版本，避免窗口缩放或源文件变动造成标注错位。
- 不要求所有模型支持视觉。文本模型使用路径、尺寸、坐标与文字反馈，并明确提示不能凭此查看图像内容。

0.4.0 不做：自动判断哪张「更美」、OCR 全量索引、任意 HTML 页面注入标注、视频逐帧标注。

### C. 消息书签与决定卡片

解决长对话里「那条要求是什么」「最后定的是哪一个方案」的问题。不同于 DSH 已有的会话置顶与搜索。

- 对某条消息添加书签、标签和个人备注，支持「约束」「已决定」「待解决」三类。
- 从侧栏列表返回具体来源；历史片段尚未加载时先定位对应回合，再按公开接口补载。原记录不可用时明确提示，不能跳到错误消息。
- 选中用户文字后可手动保存决定卡片；默认不使用额外模型请求自动归纳，后续如增加 AI 建议也必须由用户确认。
- 更改决定时保留旧版本，并标记「已被替代」；相互冲突的约束并列提示，不擅自删除其中一条。
- 「加入本次上下文」只把选中的文字及来源加入草稿，用户确认发送。收藏不等于模型已经知道，也不提升指令优先级。
- 数据按 profile/workspace/session 隔离，在 Host 本地持久保存；提供导出和删除。书签丢失或插件卸载不得修改原始会话。

## 4. 后续功能路线

### 0.5：交付、版本与交接

| 功能 | 实际使用方式 | 边界 |
| --- | --- | --- |
| 交付验收面板 | 回合结束汇总文件、变更、实际运行的验证命令和日志链接；用户为验收项选择通过/不通过/未验证 | 复用原生交付与 diff；退出码 0 只代表命令成功，不自动推断所有需求通过；无结构化证据就标记未知 |
| 产物版本架 | 对用户选中的交付文件保留 v1/v2/v3 快照，支持图片比较、文本 diff 和下载当时版本 | 这是内容快照，不是同一路径的多个链接；默认不全量备份，设总量上限、保留期限和清理入口；不覆盖源文件 |
| 可审阅交接包 | 汇总目标、确认的约束、已完成证据、未解决问题和下一步，预览后复制/导出或加入目标会话草稿 | 复用已有会话引用和查询服务；默认规则式整理，AI 摘要单独选择并提示费用；不自动创建任务或隐式跨项目记忆 |

交接包中的每条事实尽量指向来源事件。引用的命令、文件内容和外部文档仍然是数据，不会因被收藏或摘要而成为更高优先级指令。生成/保存交接包不自动修改系统提示词或 AGENTS.md。

### 0.6：待处理中心与安全文件恢复

**待处理中心**：只汇总需要用户采取行动的事件，如待审批、待回答、失败和待验收交付。支持工作区筛选、已读/待处理状态、来源跳转；展示「状态未知」而不是用旧缓存假装正常。复用原生审批入口，不做一键批量批准。通知去重并默认安静，不重复已有的回合完成成就提示。它不是另一套 Schedule 或后台任务引擎。

**安全文件检查点**：参考 Claude Code 和 Cline 的「先对比，再恢复」，但作为独立高风险阶段验收。

- 起步只覆盖明确可追踪的文件修改，显示覆盖范围；没有完整证据的 shell、副代理或外部并发修改不承诺可恢复。
- 使用独立内容存储和事件索引，不改用户 Git 的分支、索引与提交历史；也不能长期依赖 DSH 当前临时变更缓存。
- 恢复前展示差异、核对当前文件哈希、列出恢复范围，由用户明确确认。
- 保留用户开始任务前的未提交改动；遇到其他任务或用户的新改动时拒绝自动覆盖。
- 恢复前另建当前状态备份；校验失败或部分恢复失败必须报告具体范围并保留日志。
- 第一阶段只恢复文件，不删除会话历史；保留「在这里恢复了文件」的审计记录。
- 不承诺撤销 GitHub 推送、数据库操作、部署、消息发送等外部副作用；检查点不能成为降低权限要求的理由。
- 大仓库、二进制、符号/硬链接、大小写冲突、删除/改名、磁盘满、并发恢复都需要专门测试；不可恢复时明确标记。

## 5. Minecraft 外观与布局

- 图片阅览条采用地图/物品展示框语言，但图片本身保持原始颜色和比例，不叠加像素滤镜。
- 图片工作台使用宽屏容器布局；书签可用书与羽毛笔图标，产物版本用箱子图标，待处理用铃铛图标。图标不替代文字说明。
- 面板边框、按钮、布局继续采用原创 Java 版风格 UI。官方素材仍只允许用户本地导入物品贴图，不取官方 UI，不把它们打包推送。
- 长文与代码优先保证可读性，沿用已修好的字体和真实输入控件，不再叠加文字镜像层。
- 对话内结果放在正常文档流；复杂信息进可收起侧栏，窄屏切换独立面板。底部 XP/物品栏不增加新的常驻功能区。
- 动效采用短促按压、淡入和状态变化，遵守减少动效偏好；不加入影响读图的漂浮、摇晃或粒子。
- 弹窗具备焦点圈定、Escape 关闭和关闭后焦点恢复；完整支持键盘及中英文。

## 6. 技术划分与安全要求

已在 `src/client/workbench/`、`src/workbench.ts` 和 `src/host/notebook.ts` 分离界面、共享契约与 Host 存储；后续的 `evidence`、`artifact-history`、`handoff`、`attention`、`checkpoints` 仍为拟议模块。

客户端只负责交互、派生视图与受控缓存。Host 负责需持久保存的数据、授权资源读取和后续文件操作。引用现有 Session 绑定、附件读取、文件预览、查询及插槽机制，不另开未认证的静态文件服务器，不修改 DSH vendor 代码。

安全与生命周期要求：

- 读图遵循原有会话授权，不能把任意绝对路径当作可读文件接口；跨会话使用附件前重新确认访问权限。
- 图片按需加载、限制解码尺寸及缓存总量；只缓存缩略图和必要原图，切换连接及时释放 Blob URL。
- 显示图片与重新提交给模型是不同操作。标注反馈或跨会话带图可能增加 token，必须由用户发送。
- SVG 不注入应用 DOM；HTML 不作为图片执行。第一版标注导出限定栅格图像，沿用原有安全预览。
- 缓存和快照与导入素材缓存分开管理；不能因「清除素材」而误删书签或历史产物。
- 存储具备 schema 版本、原子更新和迁移失败备份；不直接编辑 DSH 的会话 JSONL。
- 新入口缺少依赖时隐藏或显示不可用；保持 DSH 原生读取、审批、消息提交和卸载恢复路径可用。
- 性能优化不依赖固定长轮询或每次消息刷新扫描全部历史；优先增量事件和可见区加载。

## 7. 实施顺序与验收

0.4.0 按以下顺序实施；后续版本继续遵守隔离验证与按当轮授权部署：

1. **接入验证**：隔离 profile，使用录制/构造事件验证图片结果、工具插槽、草稿插入、书签定位和卸载恢复。先明确实时聚合是否有公开入口，不修改用户日常 profile。
2. **图片阅览条**：先交付用户最关心的默认可见图片结果，覆盖嵌套工具、错误结果和历史重连。
3. **图片工作台**：比较、缩放、标注以及加入草稿；验证不自动发送，不修改原图。
4. **书签与决定卡片**：本地持久化、来源跳转、冲突/替代状态、导入导出。
5. **全量回归**：通过后再决定安装和发布。推送、替换日常插件、重启任务均按当轮授权执行。

发布验收门槛：

- 0/1/3/20 张图片、重复内容、同路径变更、超大图、附件失效、读取失败都有可解释表现。
- 历史刷新与重连不重复卡片，切换会话不串图，历史附件不被当前源文件偷偷替换。
- 图片分组与回合折叠不破坏原有滚动位置；用户上翻查看历史时不被新图片强制拉回底部。
- 1440、1024、640、390 像素宽度，双主题、100%/125%/150% 浏览器缩放、减少动效均验证。
- 同时存在目标、待办、运行时间、模型/权限/命令菜单时，无新增遮挡，输入字体和光标无回归。
- 标注在缩放及不同设备尺寸下定位一致；加入草稿保留现有输入，不隐式调用模型或写原文件。
- 书签在 Host 重启后可恢复；源记录缺失、分支会话、中文长文件名都有明确行为。
- 未授权附件、路径越界、畸形图片、断网、磁盘写入失败都有测试，不靠 UI 隐藏代替权限校验。
- 新模块支持逐个关闭和完全卸载；现有 32 项测试与包校验继续通过，并增加对应行为测试。
- 自动化回归不提交真实模型请求；需要真实模型验证的部分单列为经同意执行的 canary，不能将夹具测试宣称为完整在线验证。

- [Claude Code Checkpointing](https://code.claude.com/docs/en/checkpointing)：文件恢复与会话恢复分离，且 shell、其他会话和部分子代理修改存在覆盖限制。
